# สรุปงานสำหรับคุยกับเพื่อน/อาจารย์ (เพื่อขอไอเดีย)

> เป็นงานในซิมูเลเตอร์ (Gazebo) ทั้งหมด ตัวเลขทุกตัวมีที่มาใน `docs/experiment-log.md` (อ้างหัวข้อในวงเล็บ) และผมแยก "พิสูจน์แล้ว" ออกจาก "ยังไม่แน่" ไว้ชัดเจน

## 1. เล่า 1 นาที

โดรนติด LiDAR + กล้องบินสำรวจเมืองสร้างแผนที่ แล้วหุ่นบนพื้นที่มี **กล้องอย่างเดียว** ต้องหาตำแหน่งตัวเองในแผนที่นั้น ปัญหาคือแผนที่เป็นเรขาคณิต (LiDAR) แต่หุ่นเห็นแต่ภาพ และมุมมองต่างกันมาก (โดรนมองจากบน 45 ม., หุ่นมองระดับพื้นสูง 0.45 ม.) วิธีที่ผมลอง: **render แผนที่ LiDAR เป็นภาพจากมุมมองระดับพื้นถนนหลายพันมุม** เก็บว่าแต่ละ pixel มาจากจุด 3D ไหน แล้วจับคู่ภาพจากกล้องจริงกับภาพ render ด้วย LoFTR → PnP ผลคือใช้ได้ในระดับหนึ่งและมีข้อค้นพบ/ปัญหาเปิดที่อยากถามความเห็น

## 2. การตั้งค่า
- โลกจำลอง 200×200 ม. มีตึก 50 หลัง ถนนกว้าง 10 ม. ตรอกกว้าง 3 ม. (ผนังตึกใช้ texture ซ้ำ 4 แบบ)
- โดรน: บิน 4 เลนที่สูง 45 ม., FAST-LIO2 ได้ ATE **8 ซม.** บนเส้นทาง 841 ม. map 2.4 ล้านจุด (ตรวจเทียบเรขาคณิตจริง: พื้นและผนังตรงภายใน ~1 ซม.)
- หุ่นพื้น: กล้องเดียว วิ่งตามถนน
- ข้อจำกัดที่ต้องบอกก่อน: **ซิมเท่านั้น** (กล้อง pinhole แสงคงที่ ไม่มีรถ/คน), ทุกวิธีใช้ GT ที่ขั้นใดขั้นหนึ่ง (เช่น ลงสี map ด้วย pose GT), เมืองเดียว

## 3. วิธีที่เทียบ
- **M0 (baseline):** map แบบภาพจากโดรน (SIFT + SfM ที่ใช้ pose GT) = เพดานของ "map ภาพ"
- **M1 (วิธีของเรา):** map LiDAR → render + provenance (pixel→จุด 3D) → LoFTR → PnP; ค้นหา view ด้วย MegaLoc (vector); 3,360 มุมมองระดับพื้น (420 ตำแหน่ง × 8 ทิศ)
- ตัวเสริม: prior ตำแหน่งจาก odometry (จำลอง), ตัดสินใจรับ/ปฏิเสธด้วยจำนวน inlier, **เสียงข้างมากข้ามหลายเฟรม**

## 4. ผลที่มีหลักฐาน (ห้องในซิมก่อน เมืองตามหลัง)

| ข้อ | ผล | ที่มา |
|---|---|---|
| render+LoFTR ใช้ได้ แต่ SIFT ล้ม | ห้อง: M1 ได้ 86.1% vs M0 72.4% ที่เกณฑ์ (0.25 ม.,2°); SIFT บน render 0.6–2.6% | 2, 3c |
| map ภาพข้ามมุมมอง/ระดับไม่ได้ | กล้องหันกลับทิศ: M0 = 0%, M1 (render มุมสังเคราะห์) 53–56%; เมือง (โดรน→พื้น): M0 = 0% จาก 819 ภาพ | 3d, 3e, 4 |
| เหตุผลที่ map ภาพไม่ได้ | ผนังระดับถนน **64.8% ไม่มีภาพโดรนเห็นเลย** (≥3 ภาพ: 19%) | 4m |
| aliasing ในห้อง | ผนังซ้ำทำให้ได้ pose "สะท้อนผ่านกลางห้อง" 16%; แก้ texture แล้วเหลือ 1.6% | 3b, 3c |
| เมือง ไม่มี prior | ถูกหนัก (≤5 ม.,10°) ~50–55%, เชื่อ inlier ไม่ได้ | 4e |
| เมือง มี prior ±5 ม. | ~72–80% ถูกหนัก; กรอง inlier≥80: ยอมรับ ~60%, ถูก ~90% (เส้นทางใหม่ **ผิดหนัก 6%** ไม่ใช่ 1% ที่รายงานตอนแรก) | 4g, 4h, 4m |
| หลายเฟรม (เสียงข้างมาก) | ผิดหนัก 5.6% → 2.2% ที่ยอมรับ ~69%; ถูกภายใน 1 ม. 87% → 96.5% | 4n |
| ความแม่นละเอียด | พื้น error ~0.5 ม. (ถูกที่ 0.5 ม. ราว 40–50%) ยังไม่แก้ | 4i–4l |

## 5. สิ่งที่พลาดและเรียนรู้ (ควรเล่า เพราะแสดงว่าตรวจสอบเข้ม)
- โค้ด render ลำดับวาดกลับด้าน, เวลา GT เดาจากลำดับข้อความที่ไม่เชื่อถือได้, ตัวบันทึก bag ส่งข้อความช้า 2%, ค่า splat ที่จูนกับ map ห้องแต่ใช้กับ map เมือง (ผลเมือง 9.8% → 50% เมื่อแก้) — ทุกข้อจับได้ด้วยการวัด/audit
- ตัวเลขเคยดีเกินจริงจากการประเมินบนเฟรมสลับของเส้นทางเดียวกัน จึงต้องใช้เส้นทางอิสระ

## 6. ปัญหาเปิดที่อยากถามความเห็น (เตรียมคำถามเฉพาะเจาะจง)

1. **พื้น error ~0.5 ม.** error แปลสัมพันธ์กับ error การหมุน (สหสัมพันธ์ 0.95, ความชัน 35 ม./เรเดียน = ความลึกฉาก) ลองแล้วไม่ช่วย: render-and-refine, ตัดระนาบ, ล็อก pitch/roll ด้วย IMU (ดีขึ้นเล็กน้อยที่ IMU 0.1°, แย่กว่าไม่ใช้ที่ 0.5°), และ audit เทียบเรขาคณิตจริงพบว่าพิกัด 3D ต่อ pixel คลาด ~3 px (10 px ที่ช่องว่างที่เติม) แต่การแก้ให้อยู่บนรังสีกลับแย่ลง (มัธยฐาน 0.48 → 0.62 ม., ถูกภายใน 0.5 ม. 53% → 31–35%; 4o) **มีใครเคยเจอ/มีทฤษฎีไหม ว่าอะไรกำหนดความแม่นของ PnP จากโครงสร้างไกลในซอยลึก**
2. **ช่องว่างลักษณะภาพ (render vs ภาพจริง):** ทางเลือกคือจับคู่เรขาคณิตล้วน (ความลึกจากภาพ metric depth เทียบ render ความลึก, SemCityLoc) หรือเปลี่ยนตัวจับคู่ (RoMa v2) — **ทางไหนน่าเชื่อถือกว่าสำหรับ map ที่ผิวไม่สมจริง**
3. **aliasing ในเมืองที่ผนังซ้ำ:** เสียงข้างมากหลายเฟรมช่วยได้ครึ่งหนึ่ง มีวิธีที่เป็นหลักการมากกว่านี้ไหม (เช่น ความน่าจะเป็นแบบ particle/graph, ความไม่แน่นอนต่อ pose)
4. **การออกแบบการประเมินให้เชื่อถือได้:** ตอนนี้ 1 เมือง/หลายเส้นทาง จะพิสูจน์ว่า "ใช้งานจริงได้" ต้องมีอะไรอีก (หลาย world, ข้อมูลจริง, สถิติระดับเซสชัน)
5. **ช่องว่างซิมกับของจริง:** ถ้ามีข้อมูลจริงเพียงเล็กน้อย ควรเก็บอะไรก่อน
6. **งานวิจัย:** งานที่ใกล้เคียงมีอยู่ (CRISTAL 2025 render-and-match; Zhang et al. 2024 map สังเคราะห์ + NetVLAD; SemCityLoc 2026 บนโดรน) ส่วนที่น่าจะต่างคือ **การข้ามระดับ โดรนสร้าง map → กล้องพื้น** และผลการวิเคราะห์ coverage — อาจารย์เห็นว่ามีประเด็นพอไหม

## 8. คำถามที่น่าจะโดนถาม และคำตอบที่ซื่อสัตย์
- "ทำไมไม่ใช้ SLAM ด้วยกล้องบนพื้นเลย?" → ข้ออ้างคือประหยัด: กล้องราคาถูก ใช้แผนที่ที่โดรนสร้างครั้งเดียว ยังไม่ได้เทียบต้นทุน/ความแม่นกับ visual SLAM ซึ่งเป็นช่องว่างของงาน
- "เชื่อได้แค่ไหน เพราะเป็นซิม?" → ซิมพิสูจน์ได้เฉพาะว่าวิธีทำงานในสภาพควบคุมและพังตรงไหน; ใช้งานจริงต้องมีข้อมูลจริง (แผนใน `docs/evidence-plan.md`)
- "ทำไมตัวเลขต่างจากที่เคยรายงาน?" → เรามีเส้นทางอิสระและพบว่าเดิมดีเกินจริง จึงแก้ถ้อยคำ
- "แม่นแค่ไหน?" → ระดับ ~0.5 ม. มัธยฐาน, ถูกภายใน 1 ม. ~87–96% ในกลุ่มที่ยอมรับ ยังไม่ถึงเกณฑ์ผิดหนัก ≤1%
